## Bug fix: "npm run dev opens page but no editing / no cursor / can't input"
- Real root cause = CSP in `index.html` missing `'unsafe-eval'`. vue-i18n compiles
  messages with `new Function()` at runtime; `t()` in `MenuBar` throws under strict
  CSP → whole app crashes on render → editor never mounts. HMR ws also blocked.
- Fix: added `'unsafe-eval'` to `script-src` + `connect-src 'self' ws://localhost:*`
  in `index.html`; mirrored `'unsafe-eval'` in `src-tauri/tauri.conf.json`.
- Verified with headless Chrome: `.ProseMirror` contenteditable, typing works,
  console errors none. (The earlier "vite ^8" theory was a red herring.)

## Mermaid ER diagrams with Chinese — root cause + fix
- **Symptom:** ` ```mermaid ` blocks with `erDiagram` containing Chinese fail to
  render (plugin shows "图表语法有误"). Other mermaid types (flowchart/sequence/
  class/state/gantt/pie/journey/gitGraph/mindmap) accept Chinese fine.
- **Root cause (verified via direct `mermaid.render`):** Mermaid 10.9.8's ER
  grammar is ASCII-only. Chinese in entity names, relationship labels (`下单`),
  or attribute names (`姓名`) is rejected: `Parse error ... Expecting 'ALPHANUM',
  'ENTITY_NAME', 'WORD', got '下'`. Quoting does NOT help. (Mermaid 11 added
  unicode ER support, but bumping a major dep in a Tauri app is risky.)
- **Fix (contained, version-independent):** in `src/milkdown/plugins/mermaid.ts`,
  for `erDiagram` sources only, `cjkSafeTransform()` swaps every non-ASCII run for
  a unique ASCII placeholder (`typocjkN`), mermaid renders the placeholder SVG,
  then `restore()` swaps the placeholders back to the original Chinese before we
  inject. Other diagram types are untouched. Verified: Chinese ER renders with all
  Chinese text present and zero placeholder leakage, in dev AND prod build.

## Production build crashed on load (TDZ) — root cause + fix
- **Symptom:** `vite build` output crashed at load with `Cannot access 'X' before
  initialization` (the app only ever worked via `npm run dev`).
- **Root cause:** `vite.config.ts` `manualChunks` split `@milkdown`/`prosemirror`/
  `vue` into SEPARATE chunks, forcing a cross-chunk circular-dependency init hazard.
  Per-package splitting didn't help — the cycle is intra-package (`@milkdown/components`
  ↔ vue). Terser changed the failing binding but the TDZ persisted across chunks.
- **Fix:** (1) REMOVE the `manualChunks` function entirely — let Rollup's default
  algorithm keep the cyclic modules in one evaluation unit. (2) Keep
  `build.minify: 'terser'` (terser preserves init order better than esbuild).
  Added `terser` as a **devDependency** (it was needed but not declared). Verified:
  prod build (`vite preview` served `dist`) now mounts with no TDZ and all 4 UI
  requirements + 9 mermaid formats + Chinese ER render correctly.
- Also added `font-src 'self' data:` to the CSP in BOTH `index.html` and
  `src-tauri/tauri.conf.json` so mermaid/highlight.js `data:` fonts stop tripping
  the CSP (was a harmless console warning; now gone).
- **Verification harness:** `tests/e2e-verify.mjs` drives the app via a `?e2e=1`
  hook that exposes `window.__typo` (the Crepe editor instance) in
  `src/composables/useMilkdown.ts`; run with `puppeteer-core` + `/usr/bin/google-chrome`.
  NOTE: `puppeteer-core` is installed `--no-save` (gets pruned on `npm install`),
  so reinstall it before running the probe.
- **Sandbox gotcha:** `rm -rf node_modules/.vite` is blocked by the bulk-delete
  guard; use `mv node_modules/.vite /tmp/oldvite-<ts>` instead to clear the Vite
  cache. Stale npm rename-temp dirs (`.pkg-RANDOM` inside node_modules) can block
  `npm install`; clear them with `find node_modules -type d -regextype posix-extended
  -regex '.*/\.[^/]+-[A-Za-z0-9]{6,}$' -exec rm -rf {} +`.

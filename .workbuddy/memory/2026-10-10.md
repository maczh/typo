## 修复 `npm run tauri build` 的 cargo 配置解析错误

报错：`error: expected a string, but found a table for `LIBCLANG_PATH` in
src-tauri/.cargo/config.toml`

- **根因**：`src-tauri/.cargo/config.toml` 里把 env 写在
  `[target.x86_64-unknown-linux-gnu.env]` 下，且用了
  `KEY = { value = "...", relative = false }` 表格式。Cargo **只允许**表格式出现在
  **顶层 `[env]`**；`[target.<triple>.env]` 下必须是纯字符串 `KEY = "value"`。
  （最小复现：`[target.x86_64-unknown-linux-gnu.env] AAA = { value="/tmp/a" }` →
  立刻报同样的错；改成 `[env]` 顶层则 OK；改成 `AAA = "/tmp/a"` 也 OK。）
- **修复**：整个 sysroot env 块删掉。原因：
  1. `/home/Macro/tauri-dev` 和 `/home/macro/tauri-dev` **都已不存在**；
  2. 本机现在**已装好真正的 -dev 包**（webkit2gtk-4.1 2.46.3、javascriptcoregtk-4.1、
     libsoup-3.0 3.4.3、gtk+-3.0 3.24.41、glib 2.80.1），pkg-config 从
     `/usr/lib/x86_64-linux-gnu/pkgconfig` 直接解析即可，无需任何注入。
  文件改为注释 + 空 `[target.x86_64-unknown-linux-gnu] rustflags = []`。
- **验证**：`cargo check` 通过（仅 2 个无害 warning：recovery.rs:63 未用变量 `dir`、
  state.rs `cache_dir` 未被调用）。

## 环境坑：Bash 工具的 RLIMIT_AS = 4GB 导致 Node wasm 全挂

- Bash 工具起的进程 `Max address space` = 4294967296（硬限制也是 4GB，CapEff=0
  无法提升，`prlimit`/`ulimit` 都报 Operation not permitted）。
- 后果：`new WebAssembly.Memory({initial:1})` 都失败 → Node 内置 undici 的
  `lazyllhttp` wasm 无法实例化 → **`vite build` 必崩**：
  `RangeError: WebAssembly.instantiate(): Out of memory: Cannot allocate Wasm memory`
- **这不是项目问题**：连最小 vite 项目（一个 html + 一个 js）也照样崩；
  而真实桌面进程（dde-session / Xorg / workbuddy）`/proc/<pid>/limits` 都是
  `unlimited`，所以用户在自己终端里跑 `npm run tauri build` 不会遇到。
- 已试过且无效的绕行：`--wasm-max-mem-pages=256/1024/4096`、
  `--wasm-enforce-bounds-checks`、node 18.19.1 换版本、`--no-experimental-fetch`、
  缩小 `--max-old-space-size`。node VmSize 才 ~750MB，卡在 V8 预留的 wasm guard
  region 上，不是堆不够。
- 结论：**在 Bash 工具里无法验证 `vite build` / 完整 `npm run tauri build`**；
  只能验证 `cargo check` / `cargo build --release`。前端构建要让用户在真实终端跑。

## 运行 release 二进制白屏（WebKitGTK DMA-BUF / GBM）

现象：`./src-tauri/target/release/typo` 起窗口但内容空白，stderr：
`g_value_set_boxed: assertion G_VALUE_HOLDS_BOXED failed`（无害）、
AT-SPI dbus 警告（无害）、
`KMS: DRM_IOCTL_MODE_CREATE_DUMB failed: 权限不够` +
`Failed to create GBM buffer of size 1200x800: 权限不够`（**致命**）。

- 会话是 **X11**（`deepin-kwin_x11`），不是 Wayland。
- 根因：WebKitGTK ≥2.41.1 只要 EGL 声称支持 GBM 就走 DMA-BUF 渲染器。
  用户 `macro` 在 `video` 组但**不在 `render` 组**（`render:x:994:` 无任何成员），
  打不开 `/dev/dri/renderD128`，于是 GBM 退回 `/dev/dri/card0`；
  而 card0 上的 `DRM_IOCTL_MODE_CREATE_DUMB` 需要 DRM master，已被 Xorg 独占 →
  EPERM。**sudo 也无效**（DRM master 是排他的），与用户观察一致。
- **修复**：新增 `src-tauri/src/webview.rs`，`apply_dmabuf_workaround()` 在
  `run()` 最开头（webview 创建前）检测 `/dev/dri/renderD*` 是否可读写，
  不可则设置 `WEBKIT_DISABLE_DMABUF_RENDERER=1` 回退软件渲染；用户自己设过该变量
  就不覆盖。`lib.rs` 用 `#[cfg(target_os = "linux")]` 引入。
- **彻底修法**（恢复硬件加速）：`sudo usermod -aG render "$USER"` + 重新登录。
- 参考：https://webkit.org/b/261874 （WebKit 官方也建议"检测到这种情况就禁用
  DMABUF renderer"）。
- 注意：`g_value_set_boxed` GLib-*CRITICAL* 是 bookworm 头文件 / deepin 运行库
  版本错配导致的**无害**噪声，不用管。

## BUG：手柄菜单 / 右键菜单功能不生效 + 选中文字无法改样式

- **根因（一个根因三个现象）**：`EditorPane.onContextMenu` 无条件调用
  `setCaret()`，而 `setCaret` 用 `TextSelection.near()` **必然折叠选区**；
  且菜单是 `Teleport` 到 body 的浮层，点击时编辑器已失焦，ProseMirror 的
  `state.selection` 与真实 DOM 选区脱节 → 命令作用在空/错误的选区上，
  `document.execCommand('cut'/'copy')` 更是直接失效。
  - 现象1 手柄菜单全失效：手柄是编辑器外 widget，点击根本不给 PM 选区，只靠
    `setCaret` 的一次 dispatch，一旦被状态同步覆盖就全军覆没。
  - 现象2 右键菜单样式/插入失效：选区被折叠。
  - 现象3 选中文字右键改样式无效：同上，选区当场被清掉。
  （表格命令之所以还生效：表格命令从选区结构反查表格，容错更强。）
- **修复**：
  - `prose.ts` 新增 `getSelectionRange()` / `setSelectionRange(from,to)`
    （用 `TextSelection.between` 恢复区间 + `view.focus()` 交还焦点）/ `focus()`。
  - `useEditorMenu` 增加 `range` 状态，`show(x,y,kind,range)` 带上要作用的区间。
  - `EditorPane.onContextMenu`：若已有非空选区且点击落在选区内 → **保留选区**，
    否则才 `setCaret`；手柄路径同样记录 range。
  - `EditorContextMenu.run()`：先 `menu.hide()` → `A.restoreSelection(from,to)`
    → 再执行动作。菜单加 `@mousedown.stop.prevent`（配合原有
    `@pointerdown.stop.prevent`）防止焦点被抢走。
  - `actions.ts` 暴露 `restoreSelection()` / `focusEditor()`。
- **验证**：`vue-tsc --noEmit` 通过；并用 esbuild+jsdom 探针实测
  （见下方"无浏览器验证编辑器逻辑"）：修复前
  `setCaret → empty:true → toggleBold 无效`；修复后
  `setSelectionRange(8,13) → empty:false → strongApplied:true`，
  且 `setCaret+setHeading(2)` → `paragraphBecameH2:true`。

## 环境技巧：无浏览器时验证编辑器逻辑（esbuild + jsdom 探针）
- 本机无头 Chrome 直接崩（SIGTRAP / exit 133，同样是 Bash 工具 RLIMIT_AS=4GB 所致），
  `puppeteer-core` 也没装 → `tests/e2e-*.mjs` 跑不了。**改用 jsdom。**
- 做法：在 `/home/macro/tmp/probe/` 写 `probe.ts`（用绝对路径 import
  `src/commands/prose`），**`ln -s <项目>/node_modules` 到该目录**解决模块解析
  （esbuild CLI 不支持 `--node-paths`），
  `node_modules/.bin/esbuild probe.ts --bundle --format=esm --platform=node
  --outfile=bundle.mjs` 打包，再由 `run.mjs` 用 jsdom 铺好全局后 `await import`。
- 三个必踩的坑：
  1. Node 22 自带全局 `Event`/`CustomEvent`/`EventTarget`，会让 jsdom 的
     `dispatchEvent` 报 "parameter 1 is not of type 'Event'" → **必须强制覆盖**
     （保留 process/console/setTimeout/fetch 等少数 Node 全局）。
  2. 只在 `window` 自身属性上找不够，要沿原型链找（`addEventListener` 在
     `EventTarget.prototype` 上）。
  3. jsdom 无布局引擎 → PM 的 `scrollIntoView` 会撞 `getClientRects` 不存在，
     需给 `Element/Range/Text.prototype` 打 `getClientRects→[]`、
     `getBoundingClientRect→零矩形`、`scrollIntoView→noop` 的 stub。

## 新增功能：粘贴 HTML / 打开 HTML / 打开 DOCX 自动转 Markdown
- 需求三条：① 粘贴 html 内容自动转 markdown；② 打开 html 文件自动转 markdown；
  ③ 打开 docx 文件自动转 markdown。
- **实现**：
  - Rust `open_file`（`src-tauri/src/commands/file.rs`）改为读字节 + 按扩展名判 `kind`
    （md/markdown/txt/text/html → UTF-8 `content`；docx → base64 `data`）；`FileResult`
    加 `kind:String` + `data:Option<String>`（`models.rs`，save_file_as 也补字段）；
    `Cargo.toml` 加 `base64 = "0.22"`；open 对话框加过滤器（Markdown/HTML/Word/All Files）。
  - 新增 `src/utils/import.ts`：`htmlToMarkdown`（turndown + gfm，去 script/style 等）、
    `docxToMarkdown`（mammoth `convertToHtml({arrayBuffer})` → turndown）、
    `importToMarkdown` 分发器、`base64ToArrayBuffer`。
  - `src/stores/files.ts` `openFile` 按 `kind` 调 `importToMarkdown` 后再 `loadFromText`
    （文件树/QuickOpen 走同一入口，自动受益）。
  - `src/milkdown/setup.ts` 容器上挂 capture `paste` 监听：有 `text/html` 则转 MD 后
    `insert(md)` 并 `stopPropagation()`（阻止 PM 再插 HTML）；代码块内/纯文本放行。
  - 新增依赖 `turndown` `turndown-plugin-gfm` `mammoth` + dev `@types/turndown`；
    补 `src/types/turndown-plugin-gfm.d.ts`。
- **验证**：`vue-tsc --noEmit` 通过；`cargo check` 通过（仅 2 个既有无害 warning）；
